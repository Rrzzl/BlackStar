## 1. What this project is

**The Ninth Heir** is a gothic political-tragedy RPG. Codename Black Star. The player is a Witness of the Order — latest in a nine-century chain of imperial investigators — sent to adjudicate the succession of a dead emperor whose bloodline has been quietly stabilizing the galaxy.

Two genre halves:
- **Top-down overworld and hubs** — courts, towns, ship interior, dialogue scenes, regular encounters, mini-bosses.
- **Side-view platformer boss setpieces** — 5-12 handcrafted encounters. Souls-weight. The platformer substrate from M3a is the canonical implementation.

The spine of the game is the **Long Record** — a diegetic, persistent, illuminated-manuscript book that serves as save system, quest log, lore codex, and moral flagging all at once. Entries cannot be unwritten.

The tonal reference is *Chained Echoes / Lisa the Painful* for pixel craft, with Blasphemous as the north star for mood and religious-horror composition. Five authored endings plus one hidden (ζ). All are complicity. None resolve cleanly.

## 3. Architectural commitments — locked

These are settled decisions as of 2026-04-21. Work should honor them.

### Hybrid camera

- **Top-down (three-quarter) is the default.** Overworld travel, ship cabin, claimant courts, towns, dialogue hubs, Elara's library, the Tessarene bindery, Sevasti's chambers.
- **Side-view platformer is reserved for handcrafted boss encounters only.** Roughly 5-12 across the whole game.
- **The M3a platformer substrate is NOT deprecated.** It retains full value under the narrower "side-view boss combat" role.
- **Top-down controller does not exist yet.** Stubbed at `src/core/controllers/TopDownController.ts`.
- **Camera-mode switch is diegetic.** Whip-pan + parchment-edge vignette + sound cue (bell / door / quill dropped) — the Record turning the page.

### Combat

- Top-down for regular encounters, mini-bosses, exploration jumpscares, and hidden optional bosses. 4-direction movement (8 permitted), primary + secondary weapon slots, spells, iframe roll, loot drops.
- Side-view for the handcrafted boss setpieces. Full platformer rules. Gravity, jumping, commitment. Blasphemous-adjacent feel.
- Shared damage model across both: HP, stagger, iframes, status.

### Ship

- **Walkable top-down hub, not a vehicle UI.** Rooms: Cabin (desk + Long Record + save point), Bridge (travel console), Hold, Galley.
- **Unarmed.** Only defensive tool is a chaff-launcher for scripted encounters.
- **Ship combat is eliminated from scope** — weapons, shields, enemy ship AI, dogfight physics, piloting UI, transit resource management.
- **Every trip is a scripted scene** keyed to origin, destination, and story flags. Not a generic loading screen.

### Visual language

- **World layer: pixel art.** 32-40px characters. Sharp, no anti-aliasing. Long Record palette base (`#1a1410`, `#e8dcc4`, `#c9b896`, `#c9a04b`, `#f4c57a`, `#6b2818`).
- **UI layer: illuminated manuscript.** Parchment, wax, gold foil, ink, serif typography (IM Fell English, Cormorant Garamond, Uncial Antiqua).
- **The two do not bleed.** That separation is deliberate.

### Code invariants (inherited from m3a-complete, still in force)

- `src/core/` imports nothing from `@engine`, `@scenes`, or `@ui`. Verify: `grep -rn "@engine\|@scenes\|@ui" src/core` must be empty (archive under `_archive/` is excluded from live search).
- Strict TypeScript: `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`.
- Seeded RNG only in authoritative paths. `Math.random()` banned in `src/core/` and gameplay paths. Cosmetic jitter (camera shake) is the only exception.
- Save format versioned. Every schema change needs a v(n)→v(n+1) migration and test coverage.
- Scene lifecycle: `enter → update → render → exit`. Scenes may import `@engine`, `@core`, `@ui`, `@content`. Never the reverse.

## 4. Tech stack

- TypeScript (strict). Vite 5. Canvas 2D. No WebGL.
- Internal resolution: 640×360, scaled to window.
- Vitest for unit tests. Zero-warning ESLint policy.
- Save: versioned JSON in `localStorage`, migrated forward on load.
- No runtime dependencies. No Node server.

npm run dev        Vite dev server (typically http://localhost:5173/)

## 6. Scene flow (live)

```
boot
  └── TitleScene
         ├── (press ↑/↓) move menu selection
         ├── NEW WITNESS  → WitnessCreationScene (stub, no-op)
         ├── CONTINUE     → SaveSlotPicker → CabinScene (stub, no-op)
         │                  (dimmed if no saves exist)
         └── OPTIONS      → no-op

  PlanetScene                   live, reachable only by direct boot
     ├── A/D run, SPACE/W jump, F3 debug, ESC leave
     └── ESC or exit → CabinScene (stub)

  CabinScene / CourtScene /
  WitnessCreationScene /        render a single label; no input.
  ShipInteriorScene
```

Pressing any menu option in TitleScene currently lands the player in a scene that renders a single word and does nothing else. This is expected — the new architecture is scaffolded, not implemented.

`PlanetScene` still works end-to-end if you route to it directly (load a v4 save whose `scene.type === "PlanetScene"` via `TitleScene` → Continue). Platforming, coyote time, jump buffer, and exit-touch all function.

## 13. Sharp edges / things to be aware of

- **Engine is off-limits** per the current working contract. Any text rendering beyond monospace needs to reach through `renderer.ctx` directly (as `TitleScene` does) or live in a future engine extension that someone is explicitly allowed to touch.
- **Archive compiles but is opaque.** Every `.ts` file under `src/_archive/` carries `// @ts-nocheck` + `/* eslint-disable */`. Pulling anything back out of the archive requires removing those directives and restoring the imports. The archive is preservation, not a usable library.
- **Save schema is still at v4.** The fields reference the old game (`ship.moduleIds`, `sector.traders`, `sector.stockpiles`, etc.) and `SaveSnapshot` still imports `PlayerShipState`. The first post-v4 migration will be substantial — v5 is where the Long Record becomes the save.
- **`PlanetScene` has no proper entry point in the live menu.** Boot-to-PlanetScene only works via a save whose `scene.type === "PlanetScene"`. Expected — CabinScene should eventually gate entry to planet surfaces.
- **`.eslintignore` was added** to exclude the archive. Without it, archived files' `@ts-nocheck` pragmas fail the `ban-ts-comment` rule.
- **Platformer Controller retains all m3a tuning.** `runSpeed: 120, jumpVelocity: -320, coyoteTimeSec: 0.1, jumpBufferSec: 0.12, gravity: 900, terminalVelocity: 600`. First-draft numbers; the manual playthrough to validate them never happened (predecessor handoff had it queued; the project pivoted before it was done).
- **No audio cues are wired** beyond `ambient_space.mp3` and `click.mp3` (both silent-failed loads in `main.ts`). The button hook is set; no sound plays in practice.
